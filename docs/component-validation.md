# 本机验证记录（2026-10-28）

环境：Windows、RTX 4070 Ti SUPER 16GB、PyTorch 2.11.0+cu128、qwen-tts 0.1.1、官方 Base 权重、SDPA。未安装 FlashAttention；每句内部采用原生完整句子推理。

## 已验证

- 前端生产构建与桌面 Rust 构建通过。
- 前端195项测试通过；Rust61项通过，另有2项需要指定歌曲/识别样本的旧测试未运行。
- 已安装本机独立 Python、CUDA PyTorch/torchaudio，以及0.6B和1.7B两套权重。默认选0.6B，runtime.json当前配置与界面默认值一致。
- 用户提供的参考录音约23.29秒、44.1kHz双声道；原文件保持不变。取开头3.2秒生成24kHz单声道参考，原话由本地Whisper提取，写入本机qwen3-tts/voice.json，供首次配置自动导入。
- 本地HTTP服务真实生成克隆语音；响应为24kHz、单声道、s16le，WAV封装后由本地Whisper回听转写，内容基本对应预期台词。音色相似度未做主观盲测。
- 真实长句推理在发出取消后停止：从请求开始到收到取消响应约0.58秒（1.7B）与0.68秒（0.6B），含主动等待的0.5秒。取消入口使用真实HF talker停止条件；没有只丢弃HTTP结果后继续完整推理。

## 延迟与限制

| 模型与场景 | HTTP合成耗时 | 生成音频长度 |
| --- | --- | --- |
| 1.7B，首次合成含克隆提示准备 | 9.39秒 | 5.12秒 |
| 1.7B，复用提示的短句 | 2.96秒 | 1.92秒 |
| 0.6B，首次合成含克隆提示准备 | 4.56秒 | 2.00秒 |
| 0.6B，复用提示的较长句 | 4.87秒 | 3.28秒 |

这是本机单次请求观测，文字和随机生成长度不同，不能作为模型质量排名。该原生推理路径仍慢于音频播放时长，**句间可能等待下一句合成**。已实现句子流水线、有界预取和按播放时长发送PCM，但没有宣称持续无间断或97ms首包延迟。需要进一步降低延迟时应单独验证更快的推理后端；不能通过提前标记播放完成来掩盖等待。

默认模型试听生成在工作区 `.build-tmp/clone-preview-0.6b.wav`，仅包含验证台词。1.7B对照试听在 `.build-tmp/clone-preview.wav`。

所选型号现在根据实际目录解析，覆盖安装记录默认0.6B而选择已安装1.7B，以及缺少tokenizer文件的情况。已验证加载中关闭和试听中关闭不会被迟到结果覆盖，服务停止保留语音任务待确认且不停止原歌曲。Windows独立监听进程实测验证了：脚本不匹配时拒绝停止并保留进程，解释器和脚本匹配时成功关闭；测试使用独立临时端口，没有停止用户正在使用的8766服务。
