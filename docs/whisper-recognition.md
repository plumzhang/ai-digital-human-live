# 本地 Whisper 与台词结束判断

互动队列默认开启 Whisper。在队列卡片可看到模型加载状态、开关，以及当前槽位的识别文字、匹配进度和推理耗时。模型就绪后才启动自动队列；模型失效或音轨中断时保留当前任务，允许人工确认完成或跳过，不自动退回纯静音结束检测。

## 安装及切换模型

在项目根目录执行：

```powershell
npm run setup:whisper
```

脚本从 python.org 安装独立的 Python 3.12.10，从 PyPI 安装 faster-whisper 1.2.1，并从 Hugging Face 下载多语言 Whisper small。默认 CPU / int8，不修改系统 Python 或系统 PATH，不需要识别服务 Key。模型和依赖只安装一次，之后离线加载。

运行环境位于 `%LOCALAPPDATA%\com.innotechx.digitalhuman.live\whisper`，`runtime.json` 记录解释器、模型和设备。更换模型、设备后，在中控台点击“重新加载 Whisper”，或重启中控台。当前播报需先确认完成或跳过，才允许切换检测方式或重新加载。

```powershell
# 例如换用 base，减少资源消耗；中文准确率需用实际音色评估。
powershell -ExecutionPolicy Bypass -File scripts/setup-whisper.ps1 -Model base

# GPU 需要已安装 CUDA 12 cuBLAS 和 cuDNN 9，并使 DLL 可被解释器加载。
# CUDA 模式不隐式降级为 CPU；缺少依赖时会明确报错。
powershell -ExecutionPolicy Bypass -File scripts/setup-whisper.ps1 -Model small -Device cuda

# 若 CUDA DLL 不在系统 PATH，可显式保存其目录，桌面程序启动时自动加载。
powershell -ExecutionPolicy Bypass -File scripts/setup-whisper.ps1 -Model small -Device cuda -CudaLibraryDirectory 'C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.9\bin'
```

支持 tiny/base/small/medium/large-v3/turbo。使用其他目录安装时，可通过脚本的 `-RuntimeDirectory` 做独立测试；应用仍读取上述固定运行目录，需将验证通过的配置写入该目录。桌面安装包内嵌工作脚本，Python 和模型独立安装，不会从开发机绝对路径读取依赖。

## text_msg 的问答与识别目标

槽位里的“问”是通过 `text_msg` 发送给 Vidu 的内容；“答”保存同一会话当前槽位收到的 `type=10 / payload.text_msg.content` 实际输出。Whisper 继续识别 RTC 下行音频，但匹配目标改为“答”，不再把发送内容当成数字人必定逐字朗读的台词。回答的重复与累计片段会合并，输出文本、识别结果和原始发送内容一起写入队列快照及历史。OBS 弹幕回复字幕也显示实际回答。

尚未收到回答时显示“等待数字人返回回答”，匹配不会用原始发送内容兜底。Whisper 先返回时先保存音频识别结果，收到回答后重新计算匹配度。只有回答文本不足以确认音频已播完，仍需满足下面的音频与匹配条件。会话切换后的旧任务继续保留“等待人工确认”，新会话的回答不会接到旧任务上。

## 数据流及结束条件

1. 从 OBS 已订阅的远端音轨获得实际下行 PCM。分析分支保持静音，不另播声音、不采集本地麦克风。
2. AudioWorklet 输出单声道采样，在前端重采样为16kHz、16位PCM。只选择一个下行音轨用于识别，避免同一声音重复输入。
3. 按“会话ID＋任务ID＋本次播报token”录音；切换任务、结束会话、麦克风接管或断流时清除录音，忽略迟到的旧结果。
4. Whisper 常驻进程复用已加载的模型。最多一个推理请求在途，约每1.5秒处理一次当前音频；检测到350毫秒静音时补充提交句尾音频。音频滚动窗口最多约24秒，IPC 单次上限25秒；不将音频写入磁盘。
5. 识别结果保留片段及词级时间戳，繁体转简体。匹配前归一化标点、大小写、全半角和常见中文数字，按归一化后的字符数量选择范围：10字以内比较整句；11～14字也比较整句；15字及以上只比较实际回答与识别文字的最后10字。中文使用逐音节的无声调拼音容忍同音字，例如“晚晚 / 碗碗”；英文和数字逐字符比较，拼音不拼成连续字符串，以免混淆“西安 / 先”。匹配度为 `1 - 编辑距离 / 两侧较长的音节数`。承接动作开启时使用配置的触发阈值（默认50%，可设置1–100%的整数）；承接动作关闭时使用“语音识别与台词末尾匹配”的台词匹配度配置（默认70%，可设置50–100%的整数，含边界）来判断通过；不再附加完整台词88%覆盖、短句100%一致或最后两字必须相同的条件。界面显示“语音识别”、识别文字及匹配度。Whisper仍识别实际音频，此规则限定的是比较范围。完整预期台词不会被作为 Whisper 提示词，以免模型照抄台词造成假匹配。
6. 当前槽位已有语音活动且音视频健康时，承接动作开启则在匹配度达到配置阈值（默认50%）时立即确认本条并提交动作，无需等待350毫秒静音；允许推理期间继续收到本条的语音，旧会话、旧槽位及旧播报token的识别结果仍被丢弃。提交成功后等待配置时长再播下一条。承接动作关闭时，仍需达到单独配置的台词匹配度（默认70%）、匹配音频覆盖最近语音及连续静音至少350毫秒才确认本条完成并直接推进。不会再叠加900毫秒的VAD结束等待。台词匹配度与承接动作触发匹配度分别随队列自动保存；调整台词匹配度或切换结束检测方式前，需先确认完成或跳过当前播报。

350毫秒是承接动作关闭时的静音保护阈值；承接动作开启时不以此作为触发门槛。匹配结果到达时间仍取决于音频采集与本地推理速度。识别未匹配不会仅凭900毫秒静音消耗任务。保留原有60秒“等待人工确认”保护。

关闭 Whisper 后恢复原有900毫秒VAD判断。开关会随队列快照保存，不允许在正在播报或待确认时切换。

如果任务已因会话切换或重启进入“等待人工确认”，会按已保存的实际回答重新计算识别匹配度；没有实际回答的旧记录显示匹配度0%，但不会自动消耗旧任务或影响新会话。确认已经听完时，点击该任务的“确认完成”继续。

## 后续唱歌接入

唱歌模块现采用预生成的歌曲导播：整首原音频经本地 Whisper 转录为 raw.srt / whisper.json，再由大语言模型参照用户提供的完整歌词校正文案，另存 corrected.srt / timeline.json。歌曲槽位关闭实时识别，按原歌曲播放进度提前发送歌词，并以音频 ended 事件结束（包括尾奏）。500毫秒为默认提前量，可逐段调整；伴奏、拖音及实际口型同步效果仍需使用目标歌曲实测。

## 验证

```powershell
npm test
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
```

单元测试覆盖音频重采样、纯静音、在途请求上限、旧任务结果丢弃、数字/标点及同音字匹配、70%边界、10/14/15字范围切换、识别失败、断流，以及默认50%及自定义触发阈值、持续语音期间零静音提交承接动作、配置保存与范围校验、独立台词匹配度的自定义阈值与静音保护、提交后的等待时间，以及承接动作关闭时仍需350毫秒静音。

本次在 RTX 4070 Ti SUPER 上验证了本地 small / CUDA / float16：约6.4秒的中文合成测试音频单次推理约128–138毫秒，CPU / int8约1秒；纯静音返回空结果。已将本机运行配置切换到 CUDA，并保存动态库目录。以上为单个样本的推理耗时，不含采集分段、IPC、静音保护及真实RTC延迟；尚未用真实直播或歌曲验收。当前工作脚本固定使用中文识别。
