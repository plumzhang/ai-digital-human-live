# 歌曲分离与 RTC 下行人声验证

日期：2026-10-29，时间均为北京时间。测试使用用户明确授权的项目本机 Vidu API Key、已保存形象与歌曲，不记录 Key 或 RTC token。

## 最终播放流程

1. FunASR 识别原歌曲，LLM 校正歌词时间轴。
2. 本机 WSL2 使用 Demucs 4.0.1 / htdemucs 分离人声和伴奏，原歌曲保留。
3. FFmpeg 只从分离后的人声截取24kHz单声道s16le PCM。
4. OBS 按原始歌曲时间正常播放伴奏，按“PCM提前量”提前发送人声。
5. Vidu 的 RTC 下行音轨提供观众听到的人声，不同时播放本地原唱。

不增加伴奏延迟，不改变伴奏播放速度。提前量仍为0–5000毫秒，保留用户原配置，下一轮播放生效。前奏不足提前量时，发送时间最早为0，不能完全补足启动延迟。

## 真实歌曲分离

- 歌曲：《花落了一整个秋天》。
- 官方模型：[Demucs / htdemucs](https://github.com/facebookresearch/demucs)。
- 在独立 `separator` Python 环境按需运行，复用本机已安装的 CUDA torch；不安装或替换 TTS 环境中的包，不向外部分离服务上传歌曲。
- 实际使用 CUDA，完整人声与伴奏均为44,100Hz、双声道、PCM16，各12,923,064采样帧，约293.04秒。
- 人声与伴奏严格等长，共同增益0.98。两条音轨相加与相同增益原曲的最大采样误差约0.000061（PCM16量化误差范围）。
- 真实 Rust 管线 `song_stems::tests::local_real_separation_and_vocal_pcm` 已执行：生成两条分离音轨和70段人声PCM，验证人声缓存可读取、原混合歌曲不能作为该人声缓存源。
- 分离和推理完成后子进程退出，释放GPU。首次模型下载约80MB，推理不依赖正在运行的OmniVoice/FunASR服务。

分离并非无损去人声，伴奏和人声可分别试听检查残留与音质。

## 本地检查

最终前端290项测试、Rust常规99项测试、前端生产构建和Rust开发构建均通过；另显式执行1项真实歌曲分离与PCM生成测试。原有9项需本机或在线环境的Rust测试默认忽略，不计为已完成的常规测试。

覆盖以下行为：

- 旧歌曲未分离时不能入队，分离后可分别试听人声与伴奏。
- 分离结果须有完整、等长的两条音轨，原文件或分离文件变化会使缓存失效；失败不发布半成品。
- PCM提前发送不改变伴奏时钟，不在该句伴奏结束前提前释放歌曲通道。
- 歌曲播放伴奏并开启RTC人声；未订阅下行音频则拒绝启动，持续断流会停止伴奏。
- 间奏回复禁止播放本地重复PCM，VAD和FunASR从RTC音轨取样。
- 歌曲结束时若间奏回复仍在播放，保留其RTC通路到该任务结束，然后恢复普通回复的本地PCM模式。
- 取消、换会话、自动播放受限、尾音排空与旧事件隔离。

旧歌曲使用新流程前需在唱歌模块点击“分离人声与伴奏”。已在队列中的歌曲先完成或跳过，防止替换正在使用的音频文件。
