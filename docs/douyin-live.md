# douyinLive 弹幕采集

使用 [jwwsjlm/douyinLive v2.3.2](https://github.com/jwwsjlm/douyinLive/releases/tag/v2.3.2)，提交 `3b0c44876c2a`。固定的 Windows AMD64 下载地址和 SHA-256 见 `vendor/douyin-live/release.json`。准备脚本校验压缩包、提取程序与 MIT 许可证，并记录本地程序校验值；开发和打包脚本均先准备依赖。

## 连接和数据

界面接受网页直播间号、`https://live.douyin.com/<web_rid>` 和 `https://webcast.amemv.com/douyin/webcast/reflow/<room_id>`。手机端分享页先解析 `webRid`，不会将 19 位长房间 ID 错当网页号；请求去除设备和分享参数，并限制域名、路径、页面大小、重定向和超时。

客户端隐藏启动 `douyinLive.exe --sign-provider local`，选择空闲端口并生成仅本次进程使用的认证密钥。Rust 检查版本与认证后，使用 Authorization Bearer 连接本地 `/ws/<web_rid>`，将业务事件转换为原队列的持久化格式，再通过 `douyin-event` 发给界面。认证密钥不进入命令行、浏览器 URL 或前端。

弹幕仍经过过滤、归档和固定三槽位队列。入槽与数字人是否启动、自动回答是否开启无关，符合过滤规则的弹幕收到后填入空位。已入槽的内容不因30秒超时、新弹幕或新礼物自动替换，保持到完成或人工跳过；槽位2、3提前准备回答和PCM。完成或跳过后前移，并从未超过30秒的最新候选弹幕补入末尾，同一时间戳按最新接收顺序优先；礼物仅在补位时优先，不挤掉已有任务。旧版多余槽位通过 deferred_tasks 保留为候选，候选礼物和歌曲不自动过期。手动加入歌曲是固定槽位规则的显式例外：满三条时直接替换槽位3，原任务记为跳过、释放预生成音频，不回候选池；前两个槽位不动。不足三条时排在现有队尾。只有生成回答、预合成与播报需要相应数字人和自动回答状态就绪。礼物保留礼物名、数量、连击分组与结束标记。protobuf 的消息 ID、用户 ID、礼物 ID 和连击 ID 按字符串处理。旧归档目录保持兼容。

界面订阅事件后才开始连接。连接 ID 隔离旧房间的延迟事件，修改过滤规则不会重连采集。未开播、已下播和状态未知时继续等待服务轮询；房间无效或终止错误时显示原因并释放本次服务。停止采集或关闭主窗口会关闭连接和自己启动的进程。

采集服务的 `config.yaml` 和 `service.log` 位于 `%LOCALAPPDATA%/com.innotechx.digitalhuman.live/douyin-live/`。需要登录态时，停止采集，填写 `cookie.douyin` 后重新连接。采集程序和语音服务分别管理。
