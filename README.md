# 数字人直播中控台

Windows 桌面客户端，使用 Tauri 2 + Rust、Vidu S2-Avatar 实时版和 dyhub。中控台控制会话、弹幕抽取、规则过滤、人工提问和打断；独立窗口可供 OBS 使用“窗口采集”。

## 开发

需要 Windows、Node.js 20+、Rust MSVC 工具链、Visual Studio C++ Build Tools、WebView2 和 Chrome。

```powershell
npm install
npm run dev:desktop
```

打包：

```powershell
npm run package:win
```

安装包在 `src-tauri/target/release/bundle/nsis/`。`package:win` 会构建 dyhub、复制其依赖与 Node 运行时，并生成安装包。

日常调试运行 `npm run dev:desktop`，不需要安装。首次运行时若 dyhub 尚未构建，脚本会自动准备；之后前端保存即热更新，Rust 修改后由 Tauri 重新编译。

## 使用

“形象设定”通过卡片管理多个数字人，在新建或编辑卡片时可选择数字人模型 `vidu-s2`（最新模型，灰度测试中）或 `vidu-s1`，默认沿用 S2。模型选择随各自卡片保存在本机，启动会话时传给 Vidu；切换正在运行的数字人需先结束会话，再重新启动。此项与侧边栏用于优化互动提问的“模型配置”独立。

1. 进入“模型配置 → Vidu数字人”填写共用 Vidu API Key；再进入“形象设定”，点击右上角“新建数字人”或卡片上的“编辑”，填写名称、形象图片、音色和人设，点击“保存数字人”。选用的卡片点击“设为当前”。成功后重启客户端会恢复全部卡片及当前选择，包括各自的本地形象图片。Key 也会保存在本机应用存储中，可以在页面中清除。本软件不会收集 Key 或将它发送到自有服务器；调用 Vidu 接口时会直接发送给 Vidu。

   Windows 客户端同一登录会话只允许启动一个实例；数字人创建请求在后端串行执行。创建中或已有会话时，重复创建会被拒绝，以免并行创建造成积分消耗。
   填写有效 Key 后客户端调用 `GET /ent/v2/credits`，在左侧边栏底部显示积分余额；点击余额可查看资源包详情和并发额度，也可手动刷新。“高级配置”默认收起，可调整语音打断、转写、回复生成和空闲断开等参数，保存后会在“创建数字人”时随创建请求发送。
2. 在“直播中控”确认当前数字人，点击“启动数字人”，即可在没有抖音直播间时手动提问调试。启动后自动打开独立播放窗口。播放窗口用 Vidu 返回的 RTC 凭证加入 AliRTC。客户端不采集或推送本地摄像头，只订阅数字人的远端视频。本地麦克风默认不推流，点击中控台“开启麦克风推流”后采集 Windows 默认输入设备并发布到当前 RTC 会话；首次使用请允许麦克风权限，成功后“本地麦克风”显示“推流中”。点击“关闭麦克风”会停止推流并释放采集。权限拒绝、设备缺失或占用会在中控台提示原因。数字人远端音频自动订阅播放，远端视频订阅成功后绑定播放画面。中控台可随时关闭或重新开启麦克风推流。
   “生成与播放”显示创建阶段、Vidu Live 状态、会话 ID 和控制连接；RTC 入会、远端音视频订阅、实际画面、本地麦克风推流状态变化记录到操作日志，查询刷新时间、计费时长和本次积分也记录到操作日志。拿到会话 ID 后每 3 秒查询 `GET /live/v1/lives/{live_id}`；`waiting` 表示服务尚未就绪，`prepared` 表示渲染服务已准备，`on_live` 表示直播中。RTC 凭证由 Vidu 创建接口返回，无需另行配置阿里云 App ID 或密钥。
3. 输入抖音直播间的 `web_rid`，点击“启动获取弹幕”，再开启自动回答。自动队列包含 6 个槽位（含正在播报的任务），最多 2 个模型请求并发生成，Vidu 串行播报。播报期间持续接收最新候选弹幕；普通弹幕 30 秒过期，礼物优先且不打断当前台词。文本播报统一使用 Vidu 的 type=99 text_msg，支持默认千问会话。
4. OBS 添加“窗口采集”，选择“数字人画面 · OBS 窗口”。播放窗口读取实际视频分辨率，按原始宽高比自动适配，窗口总高度（含标题栏、边框）不超过当前显示器可用桌面高度的80%；横向超宽视频同时受桌面宽度限制。窗口大小由视频自动决定，避免手动拉伸或最大化产生两侧留白；视频分辨率改变时自动重新适配。
   Windows 下创建播放窗口的 Tauri 命令必须为异步命令；同步调用 `WebviewWindowBuilder` 会触发 WebView2 死锁，窗口停在空白页，而已经进入 `on_live` 的会话仍会计费。
   播放窗口会对同一会话去重入会，订阅成功后显式启动视频播放；自动播放受限时可点击“恢复播放”。中控台在操作日志记录远端订阅和实际画面播放状态，每 3 秒刷新 Live 状态并记录计费秒数和本次积分。会话空闲断开时间使用“形象与配置”的“空闲断开（秒）”，创建时传入 idle_timeout_seconds；客户端不因等待画面或未收到播放帧另设固定时限自动挂断。关闭 OBS 窗口会结束对应会话，关闭主窗口会先挂断并确认服务端 `ended`。挂断失败会保留会话并提示重试，不会仅凭本地关闭播放就宣称停止计费。
5. 在左侧“弹幕配置”的“弹幕过滤”页签配置关键词和正则。命中规则的弹幕仍显示在中控台，并附带屏蔽原因。
   点击“导出规则”下载 JSON 备份，包含全部关键词、正则及启用状态；点击“导入规则”选择 JSON 文件，与当前规则合并，相同类型和内容的重复项保留当前启用状态。导入前校验全部规则和正则，任一无效则整次导入取消并显示位置，不改变当前规则。支持导出的文件、含 rules 数组的 JSON 对象或规则数组；规则字段为 kind（keyword / regex）、value、enabled（可省略，默认启用），不复用文件中的规则 ID。文件不超过 5 MB、每次不超过 10000 条。导入后自动保存在本机。

“弹幕配置 → 弹幕设置”可实时预览 OBS 字幕，支持点击或拖动定位、水平和垂直百分比、文字区域宽度、字体与字号、加粗、对齐、颜色、整体不透明度、阴影、描边、背景及背景不透明度、内边距和圆角。入场效果可选淡入淡出、向上浮入、轻微缩放或无动画，可调节入场时长并重播预览。预览支持横屏和竖屏；位置相对于实际视频画面，字号按 1080 像素宽基准随画面缩放。设置自动保存在本机并实时同步 OBS，重开窗口后恢复；预览文字不会发送到真实字幕或口播。
   操作错误会固定显示在右上角，并保存在本机；逐条点击 × 后才会从错误日志中移除。
6. 音色克隆每次899积分（约28元），每个客户前十次克隆免费；该提示显示在克隆表单顶部。在“音色克隆”填写参考音频 URL、新音色名称和试听文本，提交后依次调用 `/ent/v2/audio-clone` 创建可试听的语音合成音色，以及 `/live/v1/voices/clone`（`provider: qwen_omni`）创建数字人直播音色。客户端在本机保存两者的关联，并在选中此音色时自动将“音色供应商”设为千问；创建实时数字人时同步发送 `voice_model.provider: qwen_omni`。“形象与配置”的音色来源分为“音色列表”和“克隆音色”：内置列表使用官方千问实时音色（56 款），支持按名称、ID、语种或场景搜索，选择后自动匹配供应商；克隆列表只显示账户中已创建的千问直播音色，排除已知豆包音色，空列表可直接前往“音色克隆”。创建数字人前会重新核实克隆音色仍存在。音色来源、名称和供应商随配置保存在本机。克隆返回的试听音频可直接播放；之后点击试听会调用 `/ent/v2/audio-tts`，可能产生用量。已列在自定义音色列表中的当前音色，也可在“形象与配置”试听。如果第二步失败，再次提交相同名称与参考音频 URL 会只重试直播音色。音色列表中的“删除”会调用 Vidu 的直播音色删除接口；删除当前音色后客户端切换为默认千问音色 Tina。

麦克风推流期间，自动队列暂停调度，仍保存收到的事件。若开启麦克风时队列正在播报，会先打断当前台词并记录为跳过；之后可重新开启自动队列。麦克风音频直接通过 AliRTC 发送给 Vidu，不会填入文字提问框。
会话创建时启用语音转写。开启麦克风后，服务端回传的用户语音识别文本会显示在 OBS 窗口视频左边缘、竖直居中位置，格式为“我：内容”；新内容替换上一句，关闭麦克风、断开连接或结束会话后清除字幕。

## 多数字人卡片

进入“形象设定”默认显示“我的数字人”卡片列表，首次升级自动将现有形象图片、音色、人设、模型及高级参数保存为“默认数字人”，原有直播间号和弹幕规则继续保留。右上角“新建数字人”可新增独立卡片，填写名称后点击“保存数字人”；卡片上的“编辑”可修改配置，“设为当前”选择用于直播的数字人。新建、编辑和取消草稿不会改动其他卡片。图片与卡片一起保存在本机 IndexedDB，重启应用仍保留；API Key 由所有数字人共用，统一在“模型配置 → Vidu数字人”设置，卡片列表和编辑页面不再显示 Key 输入框。

直播中控的“生成与播放”显示当前数字人名称，点击“启动数字人”使用所选卡片创建实时会话。直播期间可保存其他卡片，切换当前数字人或保存当前数字人的修改需先结束会话。卡片保存仅保存配置，不调用付费创建会话接口。

## 唱歌模块

唱歌模块包含“已有歌曲导播”和“生成歌曲导播”。上传原歌曲（MP3、WAV、AAC、M4A，小于100 MB，1秒～30分钟），并在文本框输入或粘贴与演唱版本一致的完整歌词。先调用本地 Whisper 转录整首歌曲，保留前奏、间奏和尾奏的绝对时间，再调用“模型配置 → 大语言模型”保存的模型参照歌词纠错。校正仅替换文字，不能改变片段数量、顺序和识别时间；校正失败时保留识别结果，可重试，也可以手动编辑时间轴。识别期间应暂停实时互动识别，避免共用本地模型时争用；切换页面不影响生成。

每首歌独立保存在应用数据目录的 songs/directors/<ID>/：原音频、lyrics.txt、Whisper 完整原始响应 whisper.json、未经校正的 raw.srt、校正后的 corrected.srt、timeline.json 和 director.json。timeline.json 每段记录 start_ms、end_ms、text、lead_ms 和 send_at_ms；默认提前量为500毫秒，发送时间为 max(0, start_ms - lead_ms)。界面可检查、编辑歌词时间及每段提前量（0～5000毫秒），保存后生效。位于歌曲开头、开始时间不足提前量的片段会在播放开始时发送。旧版离线视频文件和数据库仍保留在原目录。

点击“加入播放歌曲槽位”将导播放入现有六槽位队列；连接数字人并关闭麦克风后，手动加入的歌曲按队列顺序自动播放，无需开启“自动回答弹幕”。歌曲启动不依赖 RTC 下行音频或静音识别，OBS 会在静音数字人后清理原有语音，再播放原歌曲；前序未完成的槽位仍需先处理。若系统阻止自动播放，槽位提示等待点击恢复，点击 OBS 窗口“恢复播放”后继续。OBS 播放窗口播放原歌曲，同时屏蔽 RTC 数字人的下行声音，保留视频。歌词指令使用 Vidu type=99 text_msg，每段使用独立消息 ID，由原歌曲 currentTime 调度，避免缓冲期间字幕继续推进；字幕显示当前歌词。歌曲槽位不运行实时 Whisper，不依据 VAD、最后一句歌词或普通回复的60秒时限结束，而以原音频 ended 事件完成，包含尾奏。歌曲不被礼物挤出，也不受普通弹幕30秒过期限制。

播放结束、打断、跳过、麦克风接管和会话结束会停止原歌曲与歌词调度、清理未完成的数字人语音，并恢复正常下行声音。播放失败或长时间停滞会暂停当前槽位，需人工确认或跳过，不会自动重复播放。已排队的歌曲不能编辑或删除。此流程用于原歌曲配音、实时对口型；500毫秒是默认发送提前量，实际口型延迟仍需用目标歌曲与实时会话试听调整。

## 异步互动队列

中控台的“互动任务队列”显示六个任务槽位、提问优化状态、“问”（发给 Vidu 的提问指令）、“答”（Vidu 实际返回的答案）、错误及人工确认按钮。DeepSeek/OpenAI 兼容模型只优化提问，不代替数字人回答。例如弹幕生成“小宇问你有没有男朋友，你该怎么回答？”，礼物生成“阿豪送了玫瑰×5，你要如何谢谢他？”。礼物按采集器的 groupId/user.id/giftId 聚合累计数量；缺少连击结束状态时使用 2 秒合并窗口。当前播报中的任务不会被礼物挤出，未播的普通弹幕可以让位。没有稳定用户 ID 时不引用历史；有用户 ID 时只引用同直播间、同一观众最近三次已播报互动。

“停止获取弹幕”右侧的“测试输入弹幕”可离线导入1～6条弹幕或礼物，每条一行，空行不计数，格式为 `[弹幕][昵称] 内容//等待生成` 或 `[礼物][昵称][玫瑰×5]//等待生成`，使用已保存的模型与提问优化规则生成问题；也可将 `//` 后的内容替换为已整理好的提问指令，直接交给 Vidu 回答。输入内容中的双斜杠请写为 `／／`。先停止采集、处理完当前队列、关闭麦克风，并创建数字人，再点击“导入 N 条并开始测试”（按钮实时显示输入条数）。测试任务按输入顺序占用现有队列并持久化，不受普通直播弹幕的 30 秒过期限制；生成并发、串行播报和完成确认沿用正式队列。不需要填写直播间号或连接抖音。

状态保存在本机应用数据目录下的 `douyin-live/data`，具体绝对路径显示在队列卡片底部：

| 文件 | 用途 |
| --- | --- |
| live.db | SQLite 事务状态、原始事件、去重接收记录和历史；真实状态来源 |
| events.jsonl | 原始弹幕、礼物、关注、点赞等已接收事件 |
| queue.txt | 六行可读快照，空槽为留空行，格式为“[弹幕][昵称] 内容//优化后的提问”或“[礼物][昵称][礼物×数量]//优化后的提问” |
| queue.json | 当前窗口、候选池、合并中的礼物、状态、优化后的提问、实际回答和动作 JSON |
| playing.json | 当前播报或等待确认的任务 |
| history.jsonl | 已播报、跳过或失败的历史记录与原因 |
| persona.txt | 开启自动队列时保存的人设 |
| config.json | 3/2/1 调度参数、模型与 API 地址，不包含 API Key |

TXT/JSON 快照先写临时文件再原子替换。原始事件先进入 SQLite，队列状态提交后才记已处理；重启会恢复尚未入队的礼物。模型生成结果按任务 ID 绑定，回复乱序不会改变播报顺序。重启时可能已播出的任务保留为“等待人工确认”，不自动重复感谢。存储失败会暂停调度。生成失败保留槽位，操作员可重试或跳过。

生成结果保留 speech/intent/emotion/gesture/action_instruction/segments 字段，并增加 generation_mode=question 标记。speech 和 segments.text 保存发给 Vidu 的提问指令，不能填写主播答案；Vidu 的实际回答保存在 task.answer 中，用于“答”、OBS 字幕和语音匹配。提问需保留当前观众昵称、问题含义或礼物名称及数量，不预设感情状态等答案。重启时，旧版尚未发送的预生成答案会清除并重新生成提问；可能已发送的槽位继续保留人工确认，避免重复感谢。已优化任务可点击“重新生成”采用最新规则。

礼物提问提交后，通过独立 type=101 text_action 指令发送一个比心、亲吻手势或飞吻。普通弹幕先判断 intent：question 为问题，chat 为聊天，action_request 为明确要求执行动作。question/chat 默认发送“目光注视前方，看向镜头。”，片段动作为 idle，不额外生成微笑、点头、思考等动作。action_request（如“扎一下马尾”“涂一下口红”）按请求生成具体中文视觉动作描述。礼物事件单独处理，不能因普通弹幕声称送礼而生成礼物动作。动作支持虚拟道具，效果取决于数字人模型；动作失败不会重复发送提问。接口不提供动作成功回执或逐段时间轴，segments 仍只存档。DeepSeek/OpenAI 兼容服务需支持 Chat Completions 的 JSON 输出模式。

队列继续为任务分配不同的回答风格建议，由提问优化助手转述给 Vidu；最近开头只参考 Vidu 实际返回的回答，不将预生成提问或旧模型草稿当作已回答内容。历史仅引用同直播间同一观众最近三次已播报互动，其他观众仅使用匿名的实际回答开头，避免混淆人物。

队列默认使用本地 Whisper 识别下行音频，按整句或末10字读音计算匹配度（不足15字比较整句，15字及以上仅比较末10字）。承接动作开启时，达到可配置的触发匹配度即提交动作，默认50%，允许1–100%的整数；关闭时使用“语音识别与台词末尾匹配”里的台词匹配度（默认70%，可设置50–100%的整数），并结合至少350毫秒静音确认结束。首次执行 `npm run setup:whisper` 安装独立运行环境及多语言 small 模型；模型就绪前不启动自动队列。识别失败、断流或末尾未匹配时保留任务，不自动切换成纯静音判断。槽位显示识别文字与匹配度，开关随队列保存；关闭 Whisper 可恢复原有900毫秒VAD。详细安装、模型切换和唱歌限制见 [Whisper 说明](docs/whisper-recognition.md)。

“互动任务队列”的“承接动作”默认关闭，可选择向左下角、右下角、左上角、右上角、左侧、右侧、上方、下方查看，或平视前方。查看角度可配置为0–90度（默认30度）；选择平视前方时不使用角度，界面禁用角度输入，但保留该值供切回其他方向时使用。左下或右下方向模拟查看手机消息，其他方向自然查看后回到镜头前，平视前方则保持面对镜头的自然姿态。开关和方向随队列自动保存。语音识别匹配度达到配置的触发阈值（默认50%，可设置1–100%）、已有语音活动且音视频健康时，若承接动作开启，立即发送一次独立承接动作指令，无需等待350毫秒静音；提交成功后才开始等待所配置的0–3000毫秒（默认1699毫秒），再播报下一条已生成回复。承接动作关闭时，仍需达到单独配置的台词匹配度（默认70%）并连续静音至少350毫秒才直接推进下一条。关闭 Whisper 时使用约900毫秒VAD确认语音结束，再按承接动作开关处理。静音检测时间与动作提交后的等待时间分别计算，不会先等动作等待时长才发送指令；触发匹配度、查看角度、等待时间、开关和方向自动保存，关闭承接动作或提交失败时不增加这段等待；动作指令与状态只显示在队列和日志，不进入 OBS 字幕。跳过、暂停、旧会话和重启恢复时不自动重复发送动作；动作提交失败会显示原因，已播放的回复不会重复播报。动作渲染效果以实时画面为准，提交返回不代表动作已经完成。

## 已知接口限制

同一会话再次导入测试批次时，会清除上一轮语音检测状态，等待新收到的健康下行音频连续静音900毫秒（PCM VAD模式）后才发送首条台词，并继续遵守上一条承接动作设置的等待时间；连续点击导入不会重复入队。这个静音确认是本地观测，不代表服务端已确认动作完成。

协议排查日志保存在应用数据目录 `douyin-live/data/vidu-signals.jsonl`，包含会话ID、发送时间、信令类型、序号、消息ID、台词字数、服务端错误码和挂断原因，不记录API Key、RTC凭证或台词正文。日志达到2MB后保留上一份。`ai_output_closed` 仅说明服务端AI输出通道关闭，具体原因需关联断开前信令和Vidu服务端日志，不能仅凭这个代码判断。

直播中控台的“操作日志”下方另有“TTS 日志”，显示最近300条指令的完整正文、毫秒级发送时间、类型、发送结果、会话和消息ID。后台在实际写入控制连接后记录，覆盖中控台台词、OBS逐句歌词、动作、承接动作和打断；写入失败及连接关闭前未发送的指令显示失败。这里的“已发送”表示已写入连接，不代表数字人已经播完。完整内容保存在 `douyin-live/data/tts-log.jsonl`，超过2MB轮转并保留上一份 `tts-log.previous.jsonl`，重新打开页面或应用后恢复最近记录。该日志从功能启用后的新指令开始记录，不保存API Key或RTC凭证。

当前客户端创建的会话收到 `ai_output_closed` 时，会暂停队列，查询并确认旧会话 `ended` 后，按创建时的原配置自动重建会话，使用全新 RTC 凭证。控制连接、RTC 入会与实际画面恢复后，继续恢复前已开启的自动队列；麦克风保持关闭。中断时正在播报的任务以“播放完成情况未知、未重播”记为失败并存入历史，其余任务保留。重复通知不会并行创建；10 分钟内最多自动重建 3 次，分别等待 1/2/4 秒，状态查询、重建或存储失败即停止并提示。恢复期间点击“结束会话”会取消恢复，已经在途的新建请求返回后会自动清理。积分不足、风控、超时及主动挂断不触发此恢复。自动重建沿用正常会话计费规则；这处理的是故障后的恢复，尚不能消除 Vidu 服务端关闭输出通道的原因。

侧边栏“模型配置”顶部提供“大语言模型”和“Vidu数字人”两个页签。“Vidu数字人”统一管理所有数字人共用的 Vidu API Key，保留原先保存的 Key，并支持自动保存和清除；缺少 Key 时，形象设定和音色克隆的配置入口直接打开此页签。“大语言模型”保留原有配置，支持 OpenAI 兼容服务。默认 API 基础地址为 `https://api.openai.com/v1`，填写模型服务的 API Key 后自动查询 `/models`；也支持手动刷新、搜索模型和选择模型。选择模型后点击“保存配置”，地址、Key、模型选择和固定人设独立保存在本机，与 Vidu Key 分开。页面顶部固定显示已保存模型，重新进入或查询失败时仍保留显示。未保存的选择不会覆盖已保存配置。固定人设默认是“提问优化助手”，包含数字人晚晚的背景和期望回应风格；数字人的实际身份及回答规则在“形象设定”中配置。旧版原样默认人设自动更新为提问优化规则，自定义人设保留；可点击“恢复默认提问规则”后保存。后台始终要求只生成提问，即使旧人设要求扮演主播或直接回答也不能代写答案。队列使用结构化结果（temperature=1.0、max_tokens=640、stream=false），提问经 Vidu type=99 text_msg 发送，答案由 Vidu 会话模型生成。手动提问仍原样提交给 Vidu，不经过 DeepSeek；麦克风对话沿用 Vidu 原生语音链路。

- Vidu 实时音色克隆的 `audio_url` 最长 2048 字符。普通录音转成 data URI 会超限，因此当前客户端要求填写 Vidu 可访问的公网音频 URL；本地录音需先上传到可公开访问的存储。
- Vidu 实时音色列表只提供音色名，不提供试听音频。旧版创建的直播音色没有对应的语音合成音色关联，客户端会禁用其试听按钮；新建音色使用上述双接口流程。声音复刻接口返回的试听音频不计入永久保留条件，需在 7 天内单独调用一次语音合成接口。
- Vidu 的文字播报没有独立完成回调。OBS 通过 AliRTC getAudioTrack(远端用户ID) 获取下行音轨，用 AudioWorklet 分析约 20 毫秒 PCM 帧，执行自适应能量 VAD（60 毫秒起声确认、900 毫秒静音结束保护）。默认先用本地语音识别按整句或末10字计算读音匹配度，并检查语音活动及音视频健康；承接动作开启时，匹配度达到配置阈值（默认50%）立即发送动作指令，无需等待350毫秒静音，提交成功后等待设置的时长，再播报下一条已生成台词；承接动作关闭时，仍需达到单独配置的台词匹配度（默认70%）及连续静音至少350毫秒才直接播报下一条。关闭 Whisper 时使用900毫秒VAD确认结束，再按承接动作开关处理。确认语音结束后不会再额外等一秒才发送承接动作。检测分支静音，不重复播放，也不采集本地麦克风。音轨 mute/ended、接收停滞、分析器暂停时停止自动推进；浏览器限制音频分析时，在 OBS 点击“恢复播放”。这是本地推断，不是服务端确认；60 秒内信号不足会保留槽位为“等待人工确认”，不会因超时自动消耗任务。可点击“确认完成”或“打断并跳过”。
- 麦克风推流依赖 Windows 麦克风权限、WebView2 和真实的 Vidu RTC 会话；端到端语音交互仍需在桌面客户端实测。
- 本机需安装 Chrome 供 dyhub 默认浏览器采集内核使用。客户端仅停止它自己启动的 dyhub；如果端口 8757 已有外部 dyhub，客户端会直接连接。

dyhub 来源：[ymstar/dyhub](https://github.com/ymstar/dyhub)，MIT 许可，当前版本提交 `3f1276e21cb6e68d5b28edc152dbc4b6e96d2b43`。

内置音色目录来自 [Vidu 官方音色列表](https://platform.vidu.cn/vidu-stream/doc/voice-list?provider=ali)，仅导入 Avatar 实时版的 `ali → qwen_omni`，文档入口指向 `provider=ali`，不再提供豆包内置音色。维护时可运行 `node scripts/update-voice-catalog.mjs` 从官方文档更新本地目录；这不会创建会话或发起克隆。

已保存的豆包音色配置会自动迁移到 `qwen_omni / Tina`，保留形象图片、人设与其他参数；已有有效千问配置保持原音色。新配置默认使用 `qwen_omni / Tina`。更换配置不会改变正在运行的旧会话，需结束后重新创建数字人。

弹幕回复、手动文字回复和歌曲歌词统一通过 `type=99 / text_msg` 发送，保留任务消息 ID、毫秒时间戳、连接写入确认与错误日志，不再限制豆包供应商。`text_msg` 会进入 Vidu 对话处理。槽位以“问”展示发送内容，以“答”展示 `type=10` 返回的实际输出；Whisper 匹配实际回答，OBS 回复字幕也跟随实际回答。收到回答文本不等于播放完成，仍需实际音频与识别证据。会话切换后的待确认旧槽位保留人工确认，不将新会话输出接入旧槽位。

“提问与打断”提供两个独立输入框及发送按钮：“文本消息 text_msg”发送 `type=99 / text_msg`；“文本对话 text_dialog”发送 `type=102 / text_dialog`，只产生回复，不触发动作。两者原样提交给 Vidu，分别保留草稿，并共用手动优先队列；当前回答完成后继续自动互动。打断会停止当前输出并清除两类待发提问，TTS 日志会记录各自的指令类型。
