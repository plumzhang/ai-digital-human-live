# 数字人直播中控台

Windows 桌面客户端，使用 Tauri 2 + Rust、Vidu S2-Avatar 实时版和 dyhub。中控台控制会话、弹幕抽取、规则过滤、人工提问和打断；独立窗口可供 OBS 使用“窗口采集”。

## 开发

需要 Windows、Node.js 20+、Rust MSVC 工具链、Visual Studio C++ Build Tools、WebView2 和 Chrome。

```powershell
npm install
npm run dev:desktop
```

打包：

```powershell
npm run package:win
```

安装包在 `src-tauri/target/release/bundle/nsis/`。`package:win` 会构建 dyhub、复制其依赖与 Node 运行时，并生成安装包。

日常调试运行 `npm run dev:desktop`，不需要安装。首次运行时若 dyhub 尚未构建，脚本会自动准备；之后前端保存即热更新，Rust 修改后由 Tauri 重新编译。

## 使用

“形象与配置”最上方可选择数字人模型 `vidu-s2`（最新模型，灰度测试中）或 `vidu-s1`，默认沿用 S2。模型选择随配置保存在本机，创建会话时传给 Vidu；切换正在运行的数字人模型需先结束会话，再重新创建。此项与侧边栏用于生成弹幕回复的“模型配置”独立。

1. 在“形象与配置”填写 Vidu API Key、形象图片、音色和人设，点击“保存配置”。成功后重启客户端会恢复配置，包括所选的本地形象图片。Key 也会保存在本机应用存储中，可以在页面中清除。本软件不会收集 Key 或将它发送到自有服务器；调用 Vidu 接口时会直接发送给 Vidu。

   Windows 客户端同一登录会话只允许启动一个实例；数字人创建请求在后端串行执行。创建中或已有会话时，重复创建会被拒绝，以免并行创建造成积分消耗。
   填写有效 Key 后客户端调用 `GET /ent/v2/credits`，在左侧边栏底部显示积分余额；点击余额可查看资源包详情和并发额度，也可手动刷新。“高级配置”默认收起，可调整语音打断、转写、回复生成和空闲断开等参数，保存后会在“创建数字人”时随创建请求发送。
2. 在“直播中控”创建数字人，即可在没有抖音直播间时手动提问调试。创建后自动打开独立播放窗口。播放窗口用 Vidu 返回的 RTC 凭证加入 AliRTC。客户端不采集或推送本地摄像头，只订阅数字人的远端视频。本地麦克风默认不推流，点击中控台“开启麦克风推流”后采集 Windows 默认输入设备并发布到当前 RTC 会话；首次使用请允许麦克风权限，成功后“本地麦克风”显示“推流中”。点击“关闭麦克风”会停止推流并释放采集。权限拒绝、设备缺失或占用会在中控台提示原因。数字人远端音频自动订阅播放，远端视频订阅成功后绑定播放画面。中控台可随时关闭或重新开启麦克风推流。
   “生成与播放”显示创建阶段、Vidu Live 状态、会话 ID 和控制连接；RTC 入会、远端音视频订阅、实际画面、本地麦克风推流状态变化记录到操作日志，查询刷新时间、计费时长和本次积分也记录到操作日志。拿到会话 ID 后每 3 秒查询 `GET /live/v1/lives/{live_id}`；`waiting` 表示服务尚未就绪，`prepared` 表示渲染服务已准备，`on_live` 表示直播中。RTC 凭证由 Vidu 创建接口返回，无需另行配置阿里云 App ID 或密钥。
3. 输入抖音直播间的 `web_rid`，点击“启动获取弹幕”，再开启自动回答。自动队列包含 6 个槽位（含正在播报的任务），最多 2 个模型请求并发生成，Vidu 串行播报。播报期间持续接收最新候选弹幕；普通弹幕 30 秒过期，礼物优先且不打断当前台词。指定台词播报要求 Vidu 音色供应商为豆包。
4. OBS 添加“窗口采集”，选择“数字人画面 · OBS 窗口”。播放窗口读取实际视频分辨率，按原始宽高比自动适配，窗口总高度（含标题栏、边框）不超过当前显示器可用桌面高度的80%；横向超宽视频同时受桌面宽度限制。窗口大小由视频自动决定，避免手动拉伸或最大化产生两侧留白；视频分辨率改变时自动重新适配。
   Windows 下创建播放窗口的 Tauri 命令必须为异步命令；同步调用 `WebviewWindowBuilder` 会触发 WebView2 死锁，窗口停在空白页，而已经进入 `on_live` 的会话仍会计费。
   播放窗口会对同一会话去重入会，订阅成功后显式启动视频播放；自动播放受限时可点击“恢复播放”。中控台在操作日志记录远端订阅和实际画面播放状态，每 3 秒刷新 Live 状态并记录计费秒数和本次积分。会话空闲断开时间使用“形象与配置”的“空闲断开（秒）”，创建时传入 idle_timeout_seconds；客户端不因等待画面或未收到播放帧另设固定时限自动挂断。关闭 OBS 窗口会结束对应会话，关闭主窗口会先挂断并确认服务端 `ended`。挂断失败会保留会话并提示重试，不会仅凭本地关闭播放就宣称停止计费。
5. 在“弹幕过滤”配置关键词和正则。命中规则的弹幕仍显示在中控台，并附带屏蔽原因。
   操作错误会固定显示在右上角，并保存在本机；逐条点击 × 后才会从错误日志中移除。
6. 音色克隆每次899积分（约28元），每个客户前十次克隆免费；该提示显示在克隆表单顶部。在“音色克隆”填写参考音频 URL、新音色名称和试听文本，提交后依次调用 `/ent/v2/audio-clone` 创建可试听的语音合成音色，以及 `/live/v1/voices/clone`（`provider: doubao`）创建数字人直播音色。客户端在本机保存两者的关联，并在选中此音色时自动将“音色供应商”设为豆包；创建实时数字人时同步发送 `voice_model.provider: doubao`。“形象与配置”的音色来源分为“音色列表”和“克隆音色”：内置列表仅保留官方豆包国内实时音色，支持按名称、ID、语种或场景搜索，选择后自动匹配供应商；克隆列表只显示账户中已创建的直播音色，空列表可直接前往“音色克隆”。创建数字人前会重新核实克隆音色仍存在。音色来源、名称和供应商随配置保存在本机。克隆返回的试听音频可直接播放；之后点击试听会调用 `/ent/v2/audio-tts`，可能产生用量。已列在自定义音色列表中的当前音色，也可在“形象与配置”试听。如果第二步失败，再次提交相同名称与参考音频 URL 会只重试直播音色。音色列表中的“删除”会调用 Vidu 的直播音色删除接口；删除当前音色后客户端切换为默认豆包音色 Vivi 2.0。

麦克风推流期间，自动队列暂停调度，仍保存收到的事件。若开启麦克风时队列正在播报，会先打断当前台词并记录为跳过；之后可重新开启自动队列。麦克风音频直接通过 AliRTC 发送给 Vidu，不会填入文字提问框。
会话创建时启用语音转写。开启麦克风后，服务端回传的用户语音识别文本会显示在 OBS 窗口视频左边缘、竖直居中位置，格式为“我：内容”；新内容替换上一句，关闭麦克风、断开连接或结束会话后清除字幕。

## 异步互动队列

中控台的“互动任务队列”显示六个任务槽位、生成状态、台词、错误及人工确认按钮。礼物按采集器的 groupId/user.id/giftId 聚合累计数量；缺少连击结束状态时使用 2 秒合并窗口。当前播报中的任务不会被礼物挤出，未播的普通弹幕可以让位。没有稳定用户 ID 时不引用历史；有用户 ID 时只引用同直播间、同一观众最近三次已播报互动。

“停止获取弹幕”右侧的“测试输入弹幕”可离线导入1～6条弹幕或礼物，每条一行，空行不计数，格式为 `[弹幕][昵称] 内容//等待生成` 或 `[礼物][昵称][玫瑰×5]//等待生成`，使用已保存的模型与人设生成回复；也可将 `//` 后的内容替换为已有回答，直接播报。输入内容中的双斜杠请写为 `／／`。先停止采集、处理完当前队列、关闭麦克风，并创建使用豆包音色的数字人，再点击“导入 N 条并开始测试”（按钮实时显示输入条数）。测试任务按输入顺序占用现有队列并持久化，不受普通直播弹幕的 30 秒过期限制；生成并发、串行播报和完成确认沿用正式队列。不需要填写直播间号或连接抖音。

状态保存在本机应用数据目录下的 `douyin-live/data`，具体绝对路径显示在队列卡片底部：

| 文件 | 用途 |
| --- | --- |
| live.db | SQLite 事务状态、原始事件、去重接收记录和历史；真实状态来源 |
| events.jsonl | 原始弹幕、礼物、关注、点赞等已接收事件 |
| queue.txt | 六行可读快照，空槽为留空行，格式为“[弹幕][昵称] 内容//回答”或“[礼物][昵称][礼物×数量]//回答” |
| queue.json | 当前窗口、候选池、合并中的礼物、状态、回答和动作 JSON |
| playing.json | 当前播报或等待确认的任务 |
| history.jsonl | 已播报、跳过或失败的历史记录与原因 |
| persona.txt | 开启自动队列时保存的人设 |
| config.json | 3/2/1 调度参数、模型与 API 地址，不包含 API Key |

TXT/JSON 快照先写临时文件再原子替换。原始事件先进入 SQLite，队列状态提交后才记已处理；重启会恢复尚未入队的礼物。模型生成结果按任务 ID 绑定，回复乱序不会改变播报顺序。重启时可能已播出的任务保留为“等待人工确认”，不自动重复感谢。存储失败会暂停调度。生成失败保留槽位，操作员可重试或跳过。

生成结果含 speech/intent/emotion/gesture/action_instruction/segments。新建数字人会话开启平台默认动作库；礼物播报提交后，通过独立 type=101 text_action 指令发送一个比心、亲吻手势或飞吻。普通弹幕先判断 intent：question 为问题，chat 为聊天，action_request 为明确要求执行动作。普通问答和聊天（question/chat）默认发送“目光注视前方，看向镜头。”，片段动作为 idle，不额外生成微笑、点头、思考等动作。action_request（如“扎一下马尾”“涂一下口红”“拿一把厨房菜刀”）按请求生成对应的具体中文动作描述。每条回复在口播提交后立即发送独立动作信令。缺少或无法确定意图时默认聊天并看向镜头；旧版已预生成回复和导入回答也使用这个默认目光动作。礼物事件不受普通弹幕分类影响。动作支持虚拟道具描述，实际画面效果取决于数字人模型。队列显示动作类型及待触发、已提交、失败状态；OBS 只显示原始互动和 speech，动作元数据不进字幕或口播。动作失败不会导致重复播报或重复感谢。接口不提供动作成功回执或逐段时间轴，已提交不表示画面已完成动作，segments 仍只存档。已预生成任务可点击“重新生成”采用最新提示词。DeepSeek/OpenAI 兼容服务需支持 Chat Completions 的 JSON 输出模式。暂停队列后可等待已有模型请求结束，再进行手动提问。

自动队列的回复会随机选择起始开场方式，再为并发任务分配不同的开场要求；同时参考最近已播报和已预生成回复的匿名开头片段，避免反复使用相同句式。其他观众的完整弹幕不会混入当前观众历史。后台对已保存人设统一追加表达多样性要求，生成后去掉起头的“哎呀 / 哎哟 / 哎呦”，并同步调整动作片段台词，不增加模型请求。称呼可以出现在句中或句尾，不强制点名起手，减少复述和客服式感谢。此规则对之后新生成的任务生效，已预生成的任务可点击“重新生成”更新。

队列默认使用本地 Whisper 识别下行音频，按读音匹配度达到70%确认台词匹配（不足15字比较整句，15字及以上仅比较末10字），承接动作开启时匹配通过即提交动作，关闭时再结合至少350毫秒静音确认结束。首次执行 `npm run setup:whisper` 安装独立运行环境及多语言 small 模型；模型就绪前不启动自动队列。识别失败、断流或末尾未匹配时保留任务，不自动切换成纯静音判断。槽位显示识别文字、进度及推理耗时，开关随队列保存；关闭 Whisper 可恢复原有900毫秒VAD。详细安装、模型切换和唱歌限制见 [Whisper 说明](docs/whisper-recognition.md)。

“互动任务队列”的“承接动作”默认关闭，可选择向左下角或右下角查看，查看角度可配置为0–90度（默认45度），模拟查看手机消息。开关和方向随队列自动保存。Whisper 台词匹配度达到70%、已有语音活动且音视频健康时，若承接动作开启，立即发送一次独立承接动作指令，无需等待350毫秒静音；提交成功后才开始等待所配置的0–3000毫秒（默认1000毫秒），再播报下一条已生成回复。承接动作关闭时，仍需匹配后连续静音至少350毫秒才直接推进下一条。关闭 Whisper 时使用约900毫秒VAD确认语音结束，再按承接动作开关处理。静音检测时间与动作提交后的等待时间分别计算，不会先等动作等待时长才发送指令；查看角度、等待时间、开关和方向自动保存，关闭承接动作或提交失败时不增加这段等待；动作指令与状态只显示在队列和日志，不进入 OBS 字幕。跳过、暂停、旧会话和重启恢复时不自动重复发送动作；动作提交失败会显示原因，已播放的回复不会重复播报。动作渲染效果以实时画面为准，提交返回不代表动作已经完成。

## 已知接口限制

同一会话再次导入测试批次时，会清除上一轮语音检测状态，等待新收到的健康下行音频连续静音900毫秒（PCM VAD模式）后才发送首条台词，并继续遵守上一条承接动作设置的等待时间；连续点击导入不会重复入队。这个静音确认是本地观测，不代表服务端已确认动作完成。

协议排查日志保存在应用数据目录 `douyin-live/data/vidu-signals.jsonl`，包含会话ID、发送时间、信令类型、序号、消息ID、台词字数、服务端错误码和挂断原因，不记录API Key、RTC凭证或台词正文。日志达到2MB后保留上一份。`ai_output_closed` 仅说明服务端AI输出通道关闭，具体原因需关联断开前信令和Vidu服务端日志，不能仅凭这个代码判断。

当前客户端创建的会话收到 `ai_output_closed` 时，会暂停队列，查询并确认旧会话 `ended` 后，按创建时的原配置自动重建会话，使用全新 RTC 凭证。控制连接、RTC 入会与实际画面恢复后，继续恢复前已开启的自动队列；麦克风保持关闭。中断时正在播报的任务以“播放完成情况未知、未重播”记为失败并存入历史，其余任务保留。重复通知不会并行创建；10 分钟内最多自动重建 3 次，分别等待 1/2/4 秒，状态查询、重建或存储失败即停止并提示。恢复期间点击“结束会话”会取消恢复，已经在途的新建请求返回后会自动清理。积分不足、风控、超时及主动挂断不触发此恢复。自动重建沿用正常会话计费规则；这处理的是故障后的恢复，尚不能消除 Vidu 服务端关闭输出通道的原因。

侧边栏“音色克隆”下面的“模型配置”支持 OpenAI 兼容服务。默认 API 基础地址为 `https://api.openai.com/v1`，填写模型服务的 API Key 后自动查询 `/models`；也支持手动刷新、搜索模型和选择模型。选择模型后点击“保存配置”，地址、Key、模型选择和固定人设独立保存在本机，与 Vidu Key 分开。页面顶部固定显示已保存模型，重新进入或查询失败时仍保留显示。未保存的选择不会覆盖已保存配置。固定人设默认使用“晚晚”，可修改后保存。旧版原样默认人设自动更新为支持动作的版本，自定义人设保留；后台会追加口播与动作分开输出的规则，兼容旧人设中的纯口播或固定动作列表要求。手动文字提问和自动弹幕默认调用已保存的模型：每次独立发送 system 人设及含观众昵称、弹幕内容的 user 消息，使用 stream=false；手动文本回复 temperature=0.85、max_tokens=120，队列结构化结果 temperature=1.0、max_tokens=640，回复通过 Vidu 的 type=100 text_tts 原文播报。未保存有效配置会提示补全，不会改用 Vidu 对话模型。麦克风语音对话仍由 Vidu 原生语音链路处理。

- Vidu 实时音色克隆的 `audio_url` 最长 2048 字符。普通录音转成 data URI 会超限，因此当前客户端要求填写 Vidu 可访问的公网音频 URL；本地录音需先上传到可公开访问的存储。
- Vidu 实时音色列表只提供音色名，不提供试听音频。旧版创建的直播音色没有对应的语音合成音色关联，客户端会禁用其试听按钮；新建音色使用上述双接口流程。声音复刻接口返回的试听音频不计入永久保留条件，需在 7 天内单独调用一次语音合成接口。
- Vidu 的文字播报没有独立完成回调。OBS 通过 AliRTC getAudioTrack(远端用户ID) 获取下行音轨，用 AudioWorklet 分析约 20 毫秒 PCM 帧，执行自适应能量 VAD（60 毫秒起声确认、900 毫秒静音结束保护）。默认先用 Whisper 按整句或末10字读音匹配达到70%，并检查语音活动及音视频健康；承接动作开启时立即发送动作指令，无需等待350毫秒静音，提交成功后等待设置的时长，再播报下一条已生成台词；承接动作关闭时，仍需连续静音至少350毫秒才直接播报下一条。关闭 Whisper 时使用900毫秒VAD确认结束，再按承接动作开关处理。确认语音结束后不会再额外等一秒才发送承接动作。检测分支静音，不重复播放，也不采集本地麦克风。音轨 mute/ended、接收停滞、分析器暂停时停止自动推进；浏览器限制音频分析时，在 OBS 点击“恢复播放”。这是本地推断，不是服务端确认；60 秒内信号不足会保留槽位为“等待人工确认”，不会因超时自动消耗任务。可点击“确认完成”或“打断并跳过”。
- 麦克风推流依赖 Windows 麦克风权限、WebView2 和真实的 Vidu RTC 会话；端到端语音交互仍需在桌面客户端实测。
- 本机需安装 Chrome 供 dyhub 默认浏览器采集内核使用。客户端仅停止它自己启动的 dyhub；如果端口 8757 已有外部 dyhub，客户端会直接连接。

dyhub 来源：[ymstar/dyhub](https://github.com/ymstar/dyhub)，MIT 许可，当前版本提交 `3f1276e21cb6e68d5b28edc152dbc4b6e96d2b43`。

内置音色目录来自 [Vidu 官方音色列表](https://platform.vidu.cn/vidu-stream/doc/voice-list)，仅导入 Avatar 实时版的 `doubao3 → doubao`（仅中国区），不再提供千问音色或千问文档入口。维护时可运行 `node scripts/update-voice-catalog.mjs` 从官方文档更新本地目录；这不会创建会话或发起克隆。

已保存的千问音色配置会清空为待选，需在“形象与配置”重新选择豆包音色；新配置默认使用豆包 Vivi 2.0。更换配置不会改变正在运行的旧会话，需结束后重新创建数字人。
