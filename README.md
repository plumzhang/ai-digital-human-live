# 数字人直播中控台

Windows 桌面客户端，使用 Tauri 2 + Rust、Vidu S2-Avatar 实时版和 dyhub。中控台控制会话、弹幕抽取、规则过滤、人工提问和打断；独立窗口可供 OBS 使用“窗口采集”。

## 开发

需要 Windows、Node.js 20+、Rust MSVC 工具链、Visual Studio C++ Build Tools、WebView2 和 Chrome。

```powershell
npm install
npm run dev:desktop
```

打包：

```powershell
npm run package:win
```

安装包在 `src-tauri/target/release/bundle/nsis/`。`package:win` 会构建 dyhub、复制其依赖与 Node 运行时，并生成安装包。

日常调试运行 `npm run dev:desktop`，不需要安装。首次运行时若 dyhub 尚未构建，脚本会自动准备；之后前端保存即热更新，Rust 修改后由 Tauri 重新编译。

## 使用

1. 在“形象与配置”填写 Vidu API Key、形象图片、音色和人设，点击“保存配置”。成功后重启客户端会恢复配置，包括所选的本地形象图片。Key 也会保存在本机应用存储中，可以在页面中清除。本软件不会收集 Key 或将它发送到自有服务器；调用 Vidu 接口时会直接发送给 Vidu。

   Windows 客户端同一登录会话只允许启动一个实例；数字人创建请求在后端串行执行。创建中或已有会话时，重复创建会被拒绝，以免并行创建造成积分消耗。
   填写有效 Key 后客户端调用 `GET /ent/v2/credits`，在左侧边栏底部显示积分余额；点击余额可查看资源包详情和并发额度，也可手动刷新。“高级配置”默认收起，可调整语音打断、转写、回复生成和空闲断开等参数，保存后会在“创建数字人”时随创建请求发送。
2. 在“直播中控”创建数字人，即可在没有抖音直播间时手动提问调试。创建后自动打开独立播放窗口。播放窗口用 Vidu 返回的 RTC 凭证加入 AliRTC，并自动尝试推送本机麦克风和摄像头；首次使用请允许 Windows 设备权限。数字人远端音频自动订阅播放，远端视频订阅成功后绑定播放画面。中控台可随时关闭或重新开启麦克风、摄像头推流。
   创建时界面分别显示请求阶段、Vidu Live 状态、控制连接、RTC 入会、远端音视频订阅、本地麦克风与摄像头推流和账户并发。拿到会话 ID 后每 3 秒查询 `GET /live/v1/lives/{live_id}`；`waiting` 表示服务尚未就绪，`prepared` 表示渲染服务已准备，`on_live` 表示直播中。账户排队任务数来自 `/ent/v2/credits`，并非此 Live 的排队位置；接口未返回时显示“未返回”。RTC 凭证由 Vidu 创建接口返回，无需另行配置阿里云 App ID 或密钥。
3. 输入抖音直播间的 `web_rid`，点击“启动获取弹幕”，再开启自动回答。每 10 秒从最近 20 条合格弹幕中随机选择一条。回答期间到达的弹幕丢弃。
4. OBS 添加“窗口采集”，选择“数字人画面 · OBS 窗口”。背景为纯色。
   Windows 下创建播放窗口的 Tauri 命令必须为异步命令；同步调用 `WebviewWindowBuilder` 会触发 WebView2 死锁，窗口停在空白页，而已经进入 `on_live` 的会话仍会计费。
   播放窗口会对同一会话去重入会，订阅成功后显式启动视频播放；自动播放受限时可点击“恢复播放”。中控台分别显示远端订阅和实际画面播放状态，每 3 秒刷新 Live 状态、计费秒数和本次积分。后端在初始化成功后连续 30 秒没有收到视频播放进度时自动挂断；初始化超过 90 秒也会自动清理。关闭 OBS 窗口会结束对应会话，关闭主窗口会先挂断并确认服务端 `ended`。挂断失败会保留会话并提示重试，不会仅凭本地关闭播放就宣称停止计费。
5. 在“弹幕过滤”配置关键词和正则。命中规则的弹幕仍显示在中控台，并附带屏蔽原因。
   操作错误会固定显示在右上角，并保存在本机；逐条点击 × 后才会从错误日志中移除。
6. 在“音色克隆”填写参考音频 URL、新音色名称和试听文本，提交后依次调用 `/ent/v2/audio-clone` 创建可试听的语音合成音色，以及 `/live/v1/voices/clone`（`provider: doubao`）创建数字人直播音色。客户端在本机保存两者的关联，并在选中此音色时自动将“音色供应商”设为豆包；创建实时数字人时同步发送 `voice_model.provider: doubao`。其他来源的直播音色可在“形象与配置”手动选择克隆时的供应商。克隆返回的试听音频可直接播放；之后点击试听会调用 `/ent/v2/audio-tts`，可能产生用量。已列在自定义音色列表中的当前音色，也可在“形象与配置”试听。如果第二步失败，再次提交相同名称与参考音频 URL 会只重试直播音色。音色列表中的“删除”会调用 Vidu 的直播音色删除接口；删除当前音色后客户端切换回 Tina。

麦克风推流期间，自动弹幕提问暂停，新弹幕标记为已丢弃；关闭麦克风后恢复自动抽取。麦克风音频直接通过 AliRTC 发送给 Vidu，不会填入文字提问框。

## 已知接口限制

- Vidu 实时音色克隆的 `audio_url` 最长 2048 字符。普通录音转成 data URI 会超限，因此当前客户端要求填写 Vidu 可访问的公网音频 URL；本地录音需先上传到可公开访问的存储。
- Vidu 实时音色列表只提供音色名，不提供试听音频。旧版创建的直播音色没有对应的语音合成音色关联，客户端会禁用其试听按钮；新建音色使用上述双接口流程。声音复刻接口返回的试听音频不计入永久保留条件，需在 7 天内单独调用一次语音合成接口。
- Vidu 的文字消息和打断信令没有单独业务确认。中控台通过 RTC 音量与输出转写估计回答结束；超过 45 秒会释放忙碌状态。应在有真实 API Key 的环境中验证具体时序。
- 麦克风推流依赖 Windows 麦克风权限、WebView2 和真实的 Vidu RTC 会话；端到端语音交互仍需在桌面客户端实测。
- 本机需安装 Chrome 供 dyhub 默认浏览器采集内核使用。客户端仅停止它自己启动的 dyhub；如果端口 8757 已有外部 dyhub，客户端会直接连接。
